### 1.2.2 Node配置

> 默认配置即可

- 命令：`npm config get prefix`

  **作用**：查看 **全局包** 的安装路径前缀（即根目录）

  ```cmd
  C:\Users\loriyuhv>npm config get prefix
  D:\Program Files\nodejs
  ```

  **实际含义**：

  - 全局包会安装到 `<prefix>\node_modules` 目录
  - 全局可执行命令会放在 `<prefix>` 目录下（Windows 是 `<prefix>` 本身，Unix 系统是 `<prefix>/bin`）

- 命令：``npm config get cache`

  **作用**：查看 **npm 缓存** 的存储目录路径

  ```cmd
  C:\Users\loriyuhv>npm config get cache
  C:\Users\loriyuhv\AppData\Local\npm-cache
  ```

  **实际含义**：

  - 存放已下载的包压缩文件（`.tgz`），加速后续安装
  - 执行 `npm install` 时会优先检查缓存

  **常见用途**：

  - 清理缓存（解决安装异常）

    ```bash
    npm cache clean --force
    ```

  - 查看缓存占用空间

    ```bash
    npm cache verify
    ```

  - 修改缓存位置

    ```bash
    npm config set cache "D:\npm-cache"
    ```

- 命令：`npm config list`

  **作用**：查看所有npm配置

> **建议**：在 NVM 管理下，**不要修改 `prefix`**，保持默认即可，否则可能导致版本切换后全局包混乱。

### 8.1.2 父子通信（子传父）

- 父组件

  > 父组件定义子组件发送方法：sendIsStudentInfo
  >
  > 父组件定义父组件接收方法：getIsStudentInfo
  >
  > <student-detail :sendIsStudentInfo="getIsStudentInfo"/>
  >
  > function getIsStudentInfo(value: boolean) {
  > 	if (value) {
  > 		isStudentInfo.value = !isStudentInfo.value
  > 	}
  > }

  ```vue
  <template>
    <div class="student-center">
      <h2>学生个人中心！！！！</h2>
      <h3>学号：{{ studentInfo.studentId }}</h3>
      <p>
        <el-button v-show="!isStudentInfo" type="primary" @click="handleIsStudentInfo"
          >展示学生详细信息</el-button
        >
      </p>
    </div>
    <student-detail
      v-if="isStudentInfo"
      :studentInfo="studentInfo"
      :sendIsStudentInfo="getIsStudentInfo"
    />
  </template>
  
  <script setup lang="ts" name="StudentCenter">
  import StudentDetail from './StudentDetail.vue'
  import { ref, reactive } from 'vue'
  
  /* 数据 */
  const isStudentInfo = ref(false)
  
  const studentInfo = reactive({
    studentId: '20197360',
    studentName: '王师维',
    gender: 'male',
  })
  
  /* 函数 */
  function handleIsStudentInfo() {
    if (isStudentInfo.value) {
      isStudentInfo.value = false
      return
    }
  
    isStudentInfo.value = true
  }
  
  function getIsStudentInfo(value: boolean) {
    if (value) {
      isStudentInfo.value = !isStudentInfo.value
    }
  }
  </script>
  ```

### 8.3.0 接口类型

```typescript
// types.ts 
interface IStudentInfo {
  studentId: string

  gender: string
```

### 8.3.1 引入插件

```typescript
// 引入插件和类型
import mitt, { type Emitter } from 'mitt'
import type { IStudentInfo } from '@/api/types'

// 导出定义事件类型
export type Events = {
  // 事件名称：事件返回类型
  'send-student-info': IStudentInfo
}

// 实例化mitt
const emitter: Emitter<Events> = mitt<Events>()

export default emitter
```

### 8.3.2 组件A

## 11.3 Promise类函数

### 11.3.1 resolve函数

```typescript
// resolve()函数返回的结果是一个Promise对象；
// 注意此函数是Promise的类函数，不是实例对象的

// 1. 如果传入的参数是非Promise对象，则返回的结果是成功的Promise对象
const p1 = Promise.resolve(200)
console.log(p1)

// 2. 如果传入的参数是Promise对象，则参数的结果决定了resolve()的结果
const p2 = Promise.resolve(
    new Promise((resolve, reject) => {
        reject(401)
    }),
)
console.log(p2)  // 报错：Uncaught (in promise) 401
// 原因：由于p2是失败的Promise对象，程序没有回调对结果做处理；这种情况下，浏览器就会报此错误。
// 一个 Promise 被 reject 了，但代码里没有对它做任何 .catch() / try…catch 处理，浏览器在全局层面抛出的 未捕获拒绝（unhandled rejection） 警告；reject 的具体值恰好是 401（可能由 axios/fetch 手动 Promise.reject(401) 抛出）。

// 解决方案1
  p2.catch((reason) => {
    console.log(reason)
  })
// 解决方案2
  p2.then().catch((reason) => {
    console.log(reason)
  })
// 解决方案3
  p2.then(
    () => {},
    (reason) => {
      console.log(reason)
    },
  )

// 注意：用了p.catch(reason => {}) 就不要分开用p.then()，否则就p.then().catch()即可
```

## 11.4 Promise的几个关键问题

### 11.4.1 如何改变Promise的状态？

- resolve(value)：状态pending ====> 状态fulfiled

- reject(reason): 状态pending ====> 状态rejected

- 抛出异常：如果当前是pending就会变成rejected

  ```typescript
  const p = new Promise((resolve, reject) => {
      // 抛出错误
      throw '登录错误！！！'
  })
  
  console.log(p)
  ```

### 11.4.2 问题2

> 描述：一个Promise指定多个成功/失败回调函数，都会调用吗？
>
> 当Promise对象改变为对应状态时都会调用。

```typescript
const p = new Promise((resolve, reject) => {
    resolve('OK')
})

// 指定回调-1
p.then((value) => {
    console.log(value)
})
// 指定回调-2

```

### 11.4.3 问题3

> 改变Promise状态和指定回调函数谁先谁后？

- 都有可能，正常情况下时先指定回调再改变状态，但也可以先改变状态再指定回调。

- 如何先改状态再指定回调？

  - 在执行器中直接调用resolve()/reject()

    ```typescript
    // Promise对象内是同步任务：先改变状态，再指定回调
    // 情况一：输出：OK
    const p = new Promise((resolve, reject) => {
        resolve('OK') // 同步任务
    })
    
    p.then(
        (value) => {
            console.log(value)
        },
        (reason) => {
            console.log(reason)
        },
    )
    ```

  - 延迟更长时间才调用then()

    ```typescript
    // 异步任务：先改变状态，再指定回调
    /*
    时间轴（以代码开始运行时刻为 0s）
    0s
    	创建 Promise 实例 p，执行器内部注册第一个定时器：1000ms 后执行 reject；
    	继续往下，注册第二个定时器：2000ms 后执行 p.then ()；
    	两个定时器全部放入宏任务队列，主线程执行完毕，等待计时。
    1000ms（第 1 秒）
    	第一个定时器触发，执行 reject('error')
    	✅ Promise p 的状态被修改：pending → rejected
    	⚠重点：此时此刻，代码还没有调用 .then()！还没有绑定任何回调！
    	Promise 内部记住：状态 = rejected，结果 ='error'（状态一旦锁定永久保存）
    2000ms（第 2 秒）
    	第二个定时器触发，执行 p.then(...)
    	现在才绑定回调函数（先改变状态，后指定回调）
    	Promise 检测自身已经是 rejected 状态，直接把失败回调推入微任务队列
    	微任务执行，打印输出：error
    */
    const p = new Promise((resolve, reject) => {
        setTimeout(() => {
            reject('error')
        }, 1000)
    })
    
    setTimeout(() => {
        p.then(
            (value) => {
                console.log(value)
            },
            (reason) => {
                console.log(reason)
            },
        )
    }, 2000)
    ```

- 如何先指定回调再改变状态？

  ```typescript
  /*
  时间轴（代码启动时刻 = 0s）
  0s
  	创建 Promise 实例p，注册定时器：2000ms 后执行 reject
  	紧接着同步执行 p.then()，绑定回调函数存入 Promise 内部队列
  	✅ 先指定回调
  0~2000ms
  	Promise 保持pending状态，等待定时器触发
  2000ms
  	定时器触发，执行reject('error')
  	Promise 状态由pending → rejected
  	✅ 后改变状态
  	取出提前保存的失败回调，加入微任务队列执行，输出 error
  */
  const p = new Promise((resolve, reject) => {
      setTimeout(() => {
          reject('error')
      }, 2000)
  })
  
  p.then(
      (value) => {
          console.log(value)
      },
      (reason) => {
          console.log(reason)
      },
  )
  ```

- 什么时候才能得到数据？

  - 如果先指定回调，那状态发生改变时，回调函数就会调用，得到数据
  - 如果先改变状态，那当指定回调时，回调函数就会调用，得到数据

### 11.4.5 问题5

> Promise如何串联多个操作任务？

- Promise的then()返回一个新的Promise对象，可以开成then()的链式调用
- 通过then的链式调用串联多个同步或异步任务

```typescript
/*
0s
创建 Promise 实例p，注册定时器：1000ms后执行 resolve
紧接同步执行 p.then()，回调存入Promise内部等待列表（此时还不是微任务）
✅先指定回调

0~1000ms
Promise 保持pending状态，等待定时器触发

1000ms
定时器宏任务触发，执行resolve('ok')
Promise 状态由pending → fulfilled
✅后改变状态
取出提前保存的第一层成功回调，加入【浏览器微任务队列】
当前setTimeout宏任务执行完毕，主线程开始处理微任务队列：
1. 执行第一层then回调，输出 ok；内部new Promise立即resolve
2. 将第二层then回调再次加入微任务队列
3. 继续执行第二层微任务回调，输出 success ==> ok
*/
const p = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve('OK')
  }, 20)
})

p.then((value) => {
  console.log(value)
  return new Promise((resolve, reject) => {
    resolve('success ===>' + value)
  })
}).then((value) => {
  console.log(value)
})
```

### 11.4.6 问题6 异常穿透

- 当使用Promise的then链式调用的时候，可以在最后指定失败的回调。
- 前面任何操作出了异常，都会传到最后失败的回调中处理。

```typescript
const p = new Promise((resolve, reject) => {
  resolve('OK')
  // reject('error')
})

p.then((value) => {
  console.log('111')
  return Promise.reject('failed')
})
  .then((value) => {
    console.log('222')
  })
  .then((value) => {
    console.log('333')
    throw 'error'
  })
  .catch((reason) => {
    console.warn(reason)
  })
```

## 11.5 async与await

### 11.5.1 async函数

- 返回值：promise对象
- Promise对象的结果由async函数执行的返回值决定

```typescript
async function test() {
  // 1. 返回值是一个非Promise对象的类型，状态就是fulfilled
  // return 200
  // 2. 返回值是一个Promise对象的类型，状态由Promise对象决定
  // return Promise.resolve(200)
  // 3. 抛出异常，状态：rejected 结果：抛出异常的结果
  throw 'error'
}

const result = test()
```

### 11.5.2 await表达式

- await右侧的表达式一般为Promise对象，但也可以是其他的值
- 如果表达式是Promise对象，await返回的是Promise成功的值
- 如果表达式是其他值，直接将此值作为await的返回值

- 注意
  - await必须写在async函数中，但async函数中可以没有await
  - 如果await的Promise失败了，就会抛出异常，需要通过try。。。catch捕获处理

```typescript
async function test() {
  const p = new Promise((resolve, reject) => {
    // resolve('OK')
    reject('error')
  })
  // 1. 右侧为Promise的情况，成功的情况
  // const res1 = await p // 成功：返回Promise对象成功的值
  // console.log(res1);
  // 2 右侧为Promise的情况，失败的情况，需要try catch进行异常处理
  try {
    const res2 = await p // 失败
    console.log(res2 + '1')
  } catch (error) {
    console.log(error)
  }

  // 3. 右侧为其他类型的数据（少见）
  // const res3 = await 5
  // console.log(res3)
}

test()
```
