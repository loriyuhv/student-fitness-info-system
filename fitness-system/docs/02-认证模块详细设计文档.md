<h1><center>认证模块详细设计文档</center></h1>

# 一、模块概述

## 1\.1 模块职责

认证模块是整个体测诊断系统的**安全底座核心模块**，负责全系统用户身份认证、会话管理、令牌生命周期、权限加载、请求安全拦截、登录态销毁、强制下线等能力。

所有业务接口、租户隔离、数据权限均依赖本模块提供的身份上下文，是系统安全、数据隔离、权限控制的基础支撑。

## 1\.2 业务场景覆盖

- C端学生：账号登录、自动续期会话、个人身份识别

- 管理端教师/管理员：身份认证、角色权限加载、接口鉴权

- 系统安全能力：单点会话控制、强制下线、Token失效、会话过期、防重放、防越权

## 1\.3 核心架构特性

- **多租户隔离**：所有身份绑定 `campusId`，严格校园数据隔离

- **双Token机制**：`AccessToken`短期鉴权 \+ `RefreshToken`长期会话轮换

- **`TokenVersion` 版本失效机制**：改密、登出、踢下线批量作废旧令牌

- **`Redis`会话管控**：在线会话、黑名单、版本号统一缓存管理

- **实时权限加载**：不信任`JWT`内置权限，每次请求从`Redis`加载最新权限

- **双层异常体系**：Filter层认证异常 \+ `MVC`层业务异常完全解耦

- **双上下文线程安全**：`SecurityContext` \+ `LoginContext` 双层保障，杜绝线程泄漏

# 二、技术架构与分层设计

## 2\.1 核心技术栈

- 安全框架：Spring Security 6

- 令牌机制：`JWT` 双令牌自定义实现

- 缓存中间件：`Redis`（会话、版本、权限、黑名单）

- 上下文：`ThreadLocal` 线程级用户上下文

## 2\.2 模块分层架构（`DDD Lite` 分层）

```Plain Text
auth
├── application    # 应用服务（登录、刷新、权限查询、业务流程）
├── domain         # 领域层（会话、令牌领域规则、端口定义）
├── infrastructure # 基础设施（JWT实现、过滤器、Security配置、缓存实现）
└── handler        # 安全异常处理器

```

- **Application**：对外提供认证能力，编排登录、刷新、登出业务流程

- **Domain**：定义会话、令牌核心规则，无具体技术实现，纯粹领域逻辑

- **`Infrastructure`**：`JWT`解析、过滤器拦截、`Redis`缓存实现、Security适配

# 三、核心认证机制设计（系统亮点）

## 3\.1 双 Token 机制

#### `AccessToken`（访问令牌）

- 有效期短（`15min`）

- 用于每次接口鉴权

- 携带用户核心身份、租户、版本号信息

- 不存储权限，权限实时从`Redis`拉取

#### `RefreshToken`（刷新令牌）

- 有效期长（7天）

- 仅用于刷新 `AccessToken`，不参与业务鉴权

- 支持 Token Rotation 令牌轮换，单次有效、刷新即换新

- 绑定设备、会话，支持单点管控

## 3\.2 `TokenVersion` 全局版本失效机制（核心安全设计）

用户存在全局 **`tokenVersion`**，存储在 `Redis`。

触发版本自增场景：

- 用户主动登出

- 修改密码

- 管理员强制踢下线

校验规则：**请求Token携带的版本号 \!= `Redis`最新版本号 → 直接失效**

优势：无需维护海量黑名单，即可批量作废用户所有历史令牌。

## 3\.3 三级会话失效体系

- **版本失效**：全局强制下线

- **黑名单失效**：主动注销、踢除单次会话

- **会话下线失效**：设备会话过期、主动退出

## 3\.4 多租户身份隔离规则（强制规范）

- 租户唯一标识：`campusId`

- 所有身份上下文 Operator 必须携带 `campusId`

- **禁止前端传递租户ID**，所有租户信息仅从 Token 解析

- 所有业务查询自动拼接租户条件，杜绝跨校越权

# 四、四大核心流程设计

## 4\.1 登录流程

1. 校验账号密码，查询用户信息、所属校园

2. 读取用户当前 `TokenVersion`

3. 生成全新 `AccessToken / RefreshToken`

4. `Redis` 存入会话映射、设备会话

5. 返回双令牌与过期时间

## 4\.2 Token 刷新流程（Rotation）

1. 解析 `RefreshToken` 获取租户、用户、旧`JTI`

2. 校验会话合法性、版本合法性

3. 生成全新双令牌

4. 废弃旧会话、绑定新会话

5. 完成令牌无缝续期

## 4\.3 登出流程

1. 解析Token获取当前登录上下文

2. 删除当前设备会话、刷新令牌记录

3. **`TokenVersion` 原子自增**，作废所有旧令牌

4. 清空用户权限缓存

## 4\.4 每次请求鉴权流程（过滤器核心流程）

1. 白名单直接放行（登录、刷新）

2. 提取 Bearer Token，无Token交由Security原生处理匿名访问

3. `JWT`验签、解析、载荷校验

4. 版本号、黑名单、在线会话三层校验

5. 从`Redis`实时加载最新角色、权限

6. 构建 `SecurityContext`、`LoginContext` 双上下文

7. 请求结束双层finally兜底清空上下文

# 五、权限加载设计（安全亮点）

**系统不信任`JWT`内权限数据**。

设计原则：

- `JWT`只存身份信息，不存权限

- 每次鉴权**实时从`Redis`拉取最新权限、角色**

- 后台修改角色/权限后，用户无需重新登录即可即时生效

权限组装规则：

- 角色自动拼接 `ROLE_` 前缀

- 接口权限标识原样放行

# 六、`JWT `过滤器架构设计

## 6\.1 过滤器执行顺序

`CorsFilter → JwtAuthenticationFilter → Security原生过滤器链 → DispatcherServlet → Controller`

## 6\.2 核心能力

- 白名单精准放行

- Token解析与合法性校验

- 会话、版本、黑名单校验

- 实时权限装载

- 双上下文注入

- **双层finally线程上下文兜底清理**

## 6\.3 关键设计

**过滤器不自行写响应、不自行处理异常**。

所有认证异常统一向上抛出 `AuthenticationException`，交由 `JwtAuthenticationEntryPoint` 统一处理，保证异常收口唯一、响应格式统一。

# 七、异常分层体系设计

## 7\.1 两层异常边界（核心）

#### ① Filter 层认证异常（不走全局异常处理器）

发生在 `Servlet 过滤器`阶段，早于 `SpringMVC`，无法被 `@RestControllerAdvice `捕获。

包含：

- Token过期、签名错误、格式非法

- Token版本不匹配、会话下线、黑名单Token

- 无Token匿名访问受保护接口

统一处理器：**`JwtAuthenticationEntryPoint`**

#### ② `MVC 层`业务与权限异常（走全局异常）

- `@PreAuthorize` 方法级别权限不足

- 租户越权数据访问

- 参数校验、业务规则校验失败

统一处理器：**`GlobalExceptionHandler`**

## 7\.2 异常流转流程图（文档插图）

```Plain Text
HTTP请求
   ↓
JwtAuthenticationFilter
   ├─ 白名单 → 直接放行
   ├─ 无Token → 交由Security处理
   └─ Token校验失败 → 抛出AuthenticationException
          ↓
JwtAuthenticationEntryPoint（统一JSON返回，终止链路）
   ↓
校验全部通过 → 进入Controller
   ↓
MVC异常 → 全局异常处理器统一捕获
```

# 八、`Redis` 缓存 Key 规范设计

所有 Key 均带 **`campusId+userId`**，杜绝多租户串数据。前缀：`前缀区分业务域：auth:{子系统}:{业务}:{维度}`

- `auth:version:{campusId}:{userId}` — 用户Token版本号

- `auth:permission:{campusId}:{userId}` — 用户权限角色缓存

- `auth:session:refresh:{campusId}:{userId}` — 刷新令牌会话

- `auth:session:blacklist:{jti}` — 令牌黑名单

# 九、安全约束与开发规范

- 禁止业务代码手动解析Token，身份一律从 `LoginContext / Operator `获取

- 租户 `campusId` 永远来自上下文，禁止前端传参、禁止硬编码

- 认证异常统一由 `EntryPoint` 处理，不允许过滤器直接输出响应

- 业务校验失败统一抛出 `BizException`

- 所有接口必须经过租户隔离校验

- 请求结束必须自动清空`ThreadLocal`上下文，禁止内存泄漏

- 权限不缓存于`JWT`，必须实时从`Redis`加载

# 十、核心接口清单

- **登录接口**：账号密码登录，下发双Token

- **刷新令牌接口**：`RefreshToken`轮换续期

- **登出接口**：销毁会话、版本自增、清空缓存

# 十一、模块总结

本认证模块基于 `SpringSecurity6 + JWT + Redis` 构建，采用双Token轮换、版本号批量失效、实时权限加载、多租户隔离、双层异常体系、双上下文线程安全设计。

彻底解决了传统`JWT`系统的：**权限不即时生效、无法批量下线、过滤器异常不可控、多租户串数据、线程上下文泄漏**等经典问题，整体架构安全、规范、可扩展、可长期迭代。
